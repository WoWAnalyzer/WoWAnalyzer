# AI Usage Policy

WoWAnalyzer has strict rules for AI usage:

1. **All AI usage of any form must be disclosed.** You must state the tool you used (e.g. Claude Code, Cursor, Amp) along with the extent that the work was AI-assisted. Allowing your tool to include "Co-Authored-By" lines in commits is useful but not sufficient.
2. **You are responsible for understanding all code that you submit.** This applies both to the game knowledge that goes into the analysis and the code itself. By submitting the code, you are vouching for it. If you aren't comfortable with that, don't submit the code.
3. **Issues and discussions must not be AI-generated.** You are free to use AI based tools (such as automatic translation tools) and to use AI for brainstorming, but the text itself must not be AI generated.
4. **AI-generated media is not allowed.** This extends to images, videos, gifs, and text-based image formats like SVG. The only acceptable AI-generated content for submission is text and code.
5. **Bad AI usage will result in a project ban.** Breaking these rules, submitting obvious junk, and other bad behavior may result in a ban from the project at an Admin's discretion.

PRs from new contributors that are largely or entirely generated by LLMs will not be accepted. New contributors may still _use_ these tools, but as _tools_ and not as the primary means of producing code.

Maintainers are exempt from rule 1 because their prior participation has proven them trustworthy.

## Guidelines for Pull Requests

Narrow, focused pull requests require significantly less time and effort to review than large, monolithic PRs. Unfortunately, AI tooling encourages generating large PRs containing many distinct
changes. If you are using AI tooling to generate code, please take extra care to divide up your submissions into focused parts.

This guideline is not AI-specific, but it requires much more work to produce a problematically large PR without them.

If you are prepping a large amount of work for submission, please split it up into multiple PRs. Stacked branches are good. You can use `git rebase --interactive` to reorganize your work for this purpose.

If you submit an excessively large PR (as determined by Admins & Maintainers), you may be asked to split it up or it may be rejected without review.

## Why does this policy exist?

WoWAnalyzer is maintained by a community of volunteer contributors. Those volunteers have limited time to contribute to this project, and we do not want to spend all of that time
reviewing monolithic (and often low-quality) PRs that are primarily AI-generated.

Similarly, discussions take time and energy to interact with. While this project has not had to deal with AI-generated issues and discussions on the scale of other projects, we see
no reason to wait for it to become a problem.

This policy exists to set boundaries and to protect contributors' time.
